# Development Log - 2026-05-19

## 実施内容: note仕様変更（reCAPTCHA）完全バイパスと「二重の防衛」による大量同期（1,565件）の成功

### 1. note.com ログインブロック（reCAPTCHA）の完全バイパス
- **事象**: パスワードログインによるAPIリクエストが、note.com側のボット検知（reCAPTCHA）によって遮断されログインエラー（404/405/400等）となる。
- **対策**:
    - ブラウザ拡張機能「Cookie-Editor」からエクスポートしたJSONを、StreamlitのUI画面から直接貼り付けられる「クッキーJSON」エリアを新設。
    - 保存されたCookieデータを requests.Session にインポートしてAPIに直結する方式へ移行。

### 2. 「二重の防衛装置」の搭載（無限ループとダミーデータの完全遮断）
- **事象**: noteのAPI仕様上、全記事（1,500件以上）を遡って取得する際、ページの終端を過ぎるとダミーのゴミデータを無限に返し続けて無限ループに陥る。
- **対策**:
    - **安全装置①（重複チェック）**: タイトル名（`name`）と記事ID（`id`）を組み合わせた一意の識別子を作成し、すでに取得済みのデータしかないページに達した瞬間に `break`（取得完了）する。
    - **安全装置②（PVゼロ終端判定）**: `stats/pv?sort=pv`（PV順）でリクエストしているため、「そのページの全記事のPV合計が0」になった瞬間に、データの終端とみなして美しく正常終了させる。

### 3. 大量データ「1,565件」の整合性検証

- **備考**: noteの仕様上、ビュー集計はテキスト記事だけでなく、下書きやつぶやき、過去に削除・非公開にした記事も含まれるため、1500件を超える件数が完全に正しい真実データであることを確認。
